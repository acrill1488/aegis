\# Глава 2. Codex-архитектура AEGIS



\## 1. Цель



Создать локального ИИ-помощника наподобие Codex, который умеет:



\- читать проекты;

\- писать код;

\- изменять файлы;

\- запускать команды;

\- видеть ошибки;

\- исправлять ошибки;

\- создавать git commit;

\- работать с документацией;

\- использовать локальные модели на сервере.



\## 2. Разделение ролей



\### AEGIS-01



Рабочая станция.



Задачи:



\- хранение рабочих проектов;

\- VS Code;

\- Git;

\- агент разработки;

\- выполнение команд;

\- доступ к файлам.



\### AEGIS-SRV



Сервер моделей.



Задачи:



\- Ollama;

\- LLM-модели;

\- embeddings;

\- база знаний;

\- автоматизация;

\- долгие фоновые задачи.



\## 3. Почему агент работает на AEGIS-01



Агент должен иметь прямой доступ к файлам проекта.



Поэтому он запускается на рабочей станции, а не на сервере.



Сервер предоставляет только API модели.



\## 4. Основной стек



Минимальный стек:



\- VS Code;

\- Git;

\- Ollama server;

\- Continue.dev;

\- Cline или Roo Code;

\- Aider.



\## 5. Режимы работы



\### Chat mode



Для объяснений и вопросов.



\### Edit mode



Для изменения файлов.



\### Agent mode



Для многошаговых задач:



1\. прочитать проект;

2\. найти проблему;

3\. изменить файлы;

4\. запустить команду;

5\. проверить ошибку;

6\. исправить;

7\. сделать commit.



\## 6. Безопасность



Агент не должен иметь полный бесконтрольный доступ ко всему диску.



Рабочая зона:



F:\\AI\_WORKSPACE



Проект AEGIS:



F:\\AEGIS



Все опасные действия выполняются только после подтверждения пользователя.



\## 7. Итоговая схема



AEGIS-01:

VS Code + агент + Git + файлы



AEGIS-SRV:

Ollama + модели + база знаний
