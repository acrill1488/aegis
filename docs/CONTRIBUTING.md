# Участие в разработке AEGIS

## Стиль кода

- Следуйте руководству по стилю PEP 8 для кода на Python
- Используйте осмысленные имена переменных и функций
- Пишите четкую и краткую документацию для всех функций и классов
- Поддерживайте согласованное отступление (4 пробела)
- Держите строки длиной менее 80 символов, где это возможно
- Используйте аннотации типов для параметров функций и возвращаемых значений

## Обязательные проверки

Все вклады должны пройти следующие проверки перед принятием:

1. **Компиляция Python**: Запустите `python -m compileall` для обеспечения компиляции всех файлов Python без ошибок
2. **Проверка стиля кода**: Запустите `ruff` для проверки стиля кода и потенциальных ошибок
3. **Тестирование**: Запустите `pytest` для обеспечения прохождения всех тестов

## Изменения публичных API

- Изменения публичных API должны вноситься только при абсолютной необходимости
- Любые изменения API должны быть тщательно задокументированы
- Разрушающие изменения требуют тщательного рассмотрения и правильного версионирования
- Все публичные API должны сохранять обратную совместимость между минорными релизами

## Принцип "Architecture First"

Вся разработка должна следовать принципу "Architecture First":

1. Понимайте общую архитектуру системы перед внесением изменений
2. Убедитесь, что новые функции соответствуют существующим архитектурным паттернам
3. Поддерживайте согласованность с установленными принципами дизайна
4. Учитывайте, как изменения влияют на всю систему, а не только на отдельные компоненты
5. Предлагайте архитектурные изменения через соответствующие каналы перед реализацией

## Документация

Все изменения в коде должны сопровождаться соответствующими обновлениями документации. Это включает:
- Обновление существующих файлов документации
- Добавление новой документации для новых функций
- Обеспечение наличия примеров где это необходимо
