\# Глава 2. Проектирование инфраструктуры AEGIS



\## 1. Назначение проекта



AEGIS — локальная AI Development Platform, похожая по идее на Codex, Cursor Agent и Claude Code.



Главная задача: создать ИИ-помощника, который умеет работать с кодом, файлами, проектами, документацией и локальными моделями.



\## 2. Основная архитектура



AEGIS состоит из двух физических машин.



\### AEGIS-01



Рабочая станция.



Характеристики:



\- Ryzen 5 7400F

\- RTX 3050 8GB

\- 32 GB DDR5

\- SSD 2.5 TB

\- Windows 11 Pro



Назначение:



\- VS Code

\- Git

\- NanoCAD

\- рабочие проекты

\- Codex-подобный агент

\- запуск команд

\- изменение файлов

\- работа с терминалом



\### AEGIS-SRV



Сервер ИИ.



Характеристики:



\- Intel i5-9600KF

\- RTX 3050 8GB

\- 32 GB DDR4

\- SSD 500 GB

\- будущая ОС: Ubuntu Server 24.04 LTS



Назначение:



\- Ollama

\- локальные LLM

\- Open WebUI

\- Qdrant

\- PostgreSQL

\- Redis

\- n8n

\- MCP

\- OCR

\- Whisper

\- фоновые задачи



\## 3. Главный принцип



Агент работает на рабочем ПК, потому что именно там находятся файлы.



Модель работает на сервере, потому что сервер отдаёт вычислительные ресурсы.



Схема:



AEGIS-01:



\- VS Code

\- Roo Code / Continue / Aider

\- Git

\- PowerShell

\- проекты



AEGIS-SRV:



\- Ollama

\- Qwen Coder

\- DeepSeek Coder

\- Embeddings

\- Qdrant



\## 4. Почему не запускать агента на сервере



Сервер не должен напрямую изменять файлы рабочего ПК без контроля.



Правильная схема:



1\. Агент запущен на AEGIS-01.

2\. Он видит локальный проект.

3\. Он обращается к модели на AEGIS-SRV.

4\. Он предлагает изменения.

5\. Пользователь подтверждает.

6\. Агент меняет файлы.

7\. Агент запускает тесты.

8\. Агент делает git commit.
